메뉴 등록과 파일 업로드 구현 안내
================================

1. 설치와 실행
-------------

아래 명령은 Windows PowerShell에서 프로젝트 루트부터 실행합니다.
backend\.python-version에는 Python 3.12가 지정되어 있습니다.

    cd backend
    py -3.12 -m venv .venv
    .\.venv\Scripts\Activate.ps1
    python -m pip install -r requirements.txt

이미 backend\.venv를 만들었다면 다시 만들 필요 없이 활성화하면 됩니다.
requirements.txt에 추가한 python-multipart는 multipart/form-data 요청을
읽는 데 필요합니다. 기존 환경에서 이것만 추가 설치하려면 다음과 같이 합니다.

    python -m pip install "python-multipart>=0.0.9"

파일 업로드가 구현된 서버를 backend 디렉토리에서 실행합니다.

    python -m uvicorn main_file:a --reload --host 127.0.0.1 --port 8000

main_file:a는 main_file.py에 있는 FastAPI 객체 a를 의미합니다.
기존 main:a가 아니라 main_file:a로 실행해야 이 파일의 업로드 기능이 적용됩니다.
service\data.py가 메뉴 JSON을 상대 경로로 읽으므로 작업 디렉토리는 backend여야 합니다.

초보자용으로 주석과 처리 순서를 쉽게 풀어 쓴 서버를 사용하려면 다음처럼 실행합니다.

    python -m uvicorn main_file_eazy:a --reload --host 127.0.0.1 --port 8000

두 서버는 같은 메뉴 JSON과 업로드 폴더를 사용합니다. 같은 포트에서 두 서버를
동시에 실행할 수 없으며, 같은 JSON 파일을 함께 수정하지 않도록 하나만 실행하세요.

참고: main_file.py는 AI 채팅 서비스도 불러옵니다. 서버 시작 시 해당 서비스의
의존성, 모델 및 Google API 설정이 필요할 수 있고, 모델 준비에 시간이 걸릴 수 있습니다.


2. 클라이언트가 전송하는 형식
-----------------------------

frontend\nextjs\components\MenuInputForm.js에서 폼을 FormData로 만듭니다.

    const formData = new FormData(event.currentTarget);
    formData.set("id", "0");

현재 폼은 하나의 multipart/form-data 요청에 다음 필드를 담습니다.

    id           신규 등록 시 "0"; 실제 ID는 서버에서 새로 부여
    name         메뉴 이름
    calories     칼로리; 폼에서는 문자열로 전송
    description  설명; 빈 문자열 가능
    file         선택한 파일 한 개; 선택하지 않았다면 전송하지 않음

현재 구현은 메뉴 전체를 JSON 문자열로 묶는 것이 아니라 각 값을 폼 필드로
보냅니다. JSON 문자열을 multipart의 한 필드로 보내는 방식도 가능하지만,
현재 코드에는 그 방식이 구현되어 있지 않습니다.

frontend\nextjs\services\api.js의 addMenu는 FormData를 그대로 POST /menus에
보냅니다. 이때 Content-Type을 직접 지정하지 않아야
브라우저가 multipart 경계값(boundary)을 포함해 설정할 수 있습니다.
이제 addMenu에 JSON 객체를 전달하는 방식은 사용하지 않습니다.
main_file_eazy.py의 메뉴 등록도 폼 데이터만 받습니다.
main_file.py의 메뉴 등록은 별도로 기존 JSON 요청도 지원합니다.
메뉴 수정과 AI 채팅은 기존처럼 JSON을 사용합니다.


3. 서버 코드 작성 순서
----------------------

아래 (1)~(6)은 JSON과 폼을 모두 받는 main_file.py의 처리 과정입니다.
main_file_eazy.py에서는 POST /menus의 매개변수에 Form(...)과 File(None)을
직접 사용하여 JSON 분기와 별도의 메뉴 검증 코드를 없앴습니다.
FastAPI가 필수 값과 id, calories의 정수 타입을 검사합니다. description과
file은 선택 사항이며, 이후 파일과 메뉴의 저장 방법은 동일합니다.
일반 def로 만든 엔드포인트는 FastAPI가 스레드에서 실행합니다.

(1) 필요한 도구 가져오기

main_file.py에서 Request로 요청을 읽고, UploadFile로 파일 여부를 확인합니다.
Path로 저장 경로를 만들고, uuid4로 중복을 피할 저장 파일명을 생성합니다.
shutil.copyfileobj는 업로드된 파일 내용을 디스크 파일에 복사합니다.
Menu 모델과 ValidationError는 메뉴 필드의 타입 검증에 사용합니다.

(2) 저장 위치 지정

    UPLOAD_DIR = Path(__file__).resolve().parent / "storage" / "uploads"

이 경로는 backend\storage\uploads입니다. 폴더가 없으면 첨부파일을
저장할 때 생성합니다. 이 폴더는 .gitignore에 포함되어 Git에 올라가지 않습니다.

(3) POST 요청의 Content-Type 확인

add_menus에서 Content-Type에 따라 처리합니다.

    application/json      본문을 JSON으로 읽고 파일 없이 저장
    multipart/form-data   폼 필드와 선택적인 file을 읽어 저장
    그 외                 415 오류 응답

multipart는 request.form()으로 읽습니다. 메뉴 필드는 id, name, calories,
description이라는 이름으로 가져오고 file은 UploadFile인지 확인합니다.
이름이 프런트엔드의 필드명과 일치해야 합니다.

(4) 메뉴 검증

validate_menu에서 Menu.model_validate(values)를 호출합니다.
예를 들어 폼에서 전달한 calories 문자열 "123"은 정수 123으로 변환됩니다.
필수 필드가 없거나 타입을 변환할 수 없으면 422 오류를 응답합니다.
JSON 문법이 잘못된 경우에는 400 오류를 응답합니다.

(5) 파일과 메뉴 저장

save_menu는 파일이 있으면 임의의 이름으로 파일을 복사합니다.
이후 원본 이름과 저장된 이름을 attachment 딕셔너리로 만들어
service\data.py의 add_menu에 메뉴와 함께 전달합니다.
파일이 없을 때는 attachment 없이 메뉴만 저장합니다.
파일 복사에 실패하면 불완전한 파일을 지웁니다. 메뉴 저장에 실패하면
메모리에 추가한 메뉴와 이미 복사한 첨부파일을 정리하고 오류를 전달합니다.
파일 및 JSON 저장은 동기 작업이므로 run_in_threadpool에서 실행합니다.

(6) 메뉴 JSON에 첨부파일 정보 기록

service\data.py의 add_menu는 첨부파일이 있을 때만 메뉴에 attachment를
추가하고 backend\storage\menus_recommendation.json에 저장합니다.
저장 예시는 다음과 같습니다.

    {
        "id": 1,
        "name": "비빔밥",
        "calories": 550,
        "description": "메뉴 설명",
        "recommendation": 0,
        "attachment": {
            "filename": "menu.jpg",
            "stored_filename": "서버가_생성한_임의의_이름"
        }
    }

filename은 사용자가 선택한 원본 이름이고, stored_filename은 uploads
폴더에 저장된 실제 파일 이름입니다. 저장 이름에는 원본 확장자가 붙지 않습니다.
파일이 없는 메뉴에는 attachment 필드가 없습니다.


4. 직접 요청해 보기
-------------------

서버를 실행한 상태에서 다른 PowerShell 창을 엽니다. 아래 파일 경로는 실제
존재하는 파일로 바꾸세요. 이 요청은 실제 메뉴 데이터에 새 항목을 추가합니다.

    curl.exe -X POST http://127.0.0.1:8000/menus `
      -F "id=0" -F "name=menu" -F "calories=550" `
      -F "description=example" -F "file=@C:\temp\menu.jpg"

파일 없이 보내려면 마지막 -F "file=..." 항목을 생략합니다.
성공 응답은 {"message":"ok"}입니다. GET /menus 또는 GET /menus/{id}에서
메뉴와 attachment 정보를 확인하고 uploads 폴더에서 파일을 확인할 수 있습니다.

main_file.py를 실행한 경우에만 기존 JSON 요청을 다음처럼 시험할 수 있습니다.
main_file_eazy.py의 메뉴 등록에는 JSON을 보낼 수 없습니다.

    $menu = @{ id = 0; name = "menu"; calories = 550; description = "example" }
    Invoke-RestMethod -Uri "http://127.0.0.1:8000/menus" -Method Post `
      -ContentType "application/json" -Body ($menu | ConvertTo-Json)

자동 테스트는 backend 디렉토리에서 다음 명령으로 실행합니다.
테스트는 임시 폴더를 사용하며 실제 메뉴 JSON을 수정하지 않습니다.
테스트에 필요한 httpx가 없다면 해당 환경에 별도로 설치해야 합니다.

    python -m unittest testcode.test_main_file_upload -v


5. 현재 범위와 주의 사항
------------------------

- 첨부파일은 등록 시 한 개만 선택할 수 있습니다.
- 메뉴 목록에서 파일을 다운로드할 수 있고 JPG, PNG, GIF, WebP, BMP, AVIF는
  섬네일로 표시됩니다. 기존에 확장자 없이 저장한 파일도 원래 파일명으로 판단합니다.
- GET /menus/{id}/attachment는 원래 파일명으로 다운로드합니다.
  GET /menus/{id}/attachment?preview=true는 지원하는 이미지를 표시합니다.
  섬네일은 원본 이미지를 작게 표시하며 별도의 작은 이미지 파일을 만들지 않습니다.
- 파일 삭제 API는 아직 없습니다. 메뉴를 삭제해도 저장 파일은 남습니다.
- 파일 크기나 종류에 대한 제한은 아직 구현하지 않았습니다.
- 업로드 폴더와 메뉴 JSON을 함께 백업해야 연결 정보를 보존할 수 있습니다.
- 운영 환경에서는 파일 크기 제한, 접근 권한, 파일 검사, 저장 공간과 동시 처리
  등을 별도로 설계해야 합니다.
