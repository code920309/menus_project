JWT 회원가입과 로그인 수업 노트
==============================

1. 목표와 화면
-------------
- Header에 user : 손님을 보여 주고 회원가입/로그인 버튼으로 모달을 엽니다.
- 이메일, 비밀번호(8~128자), 연락처로 회원가입하고 별도로 로그인합니다.
- 이름 입력란이 없으므로 student@example.com은 student님으로 표시합니다.
- 로그인 후 로그아웃할 수 있으며, 메뉴 등록은 로그인한 사람만 가능합니다.
- 조회, 추천, 수정, 삭제 등 기존 기능의 권한은 이번 수업에서 변경하지 않습니다.

2. 실행하기 (Windows PowerShell, 터미널 두 개)
----------------------------------------------
백엔드 터미널: 프로젝트 루트에서
  cd backend
  .\.venv\Scripts\python.exe -m pip install "PyJWT>=2.8.0,<3"
  $env:JWT_SECRET = & .\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(48))"
  .\.venv\Scripts\python.exe -m uvicorn main_file_eazy_jwt:a --reload

이미 필요한 패키지가 설치된 가상환경을 사용하는 예입니다. 새 환경이라면
기존 백엔드의 의존성도 설치해야 합니다. JWT_SECRET은 32바이트 이상의 예측할 수
없는 값이어야 합니다. 위 명령은 현재 터미널에만 설정하므로 서버를 다시 시작할 때
새 키를 만들면 이전 JWT가 모두 무효화됩니다. 수업을 지속하려면 안전하게 보관한
동일한 키를 환경변수로 설정하세요. 키를 소스, 저장소, 수업 화면에 공개하지 마세요.
main_file_eazy.py가 아니라 복사해서 만든 main_file_eazy_jwt.py를 실행해야 합니다.
기존 서버가 같은 포트에서 실행 중이면 먼저 해당 서버를 정상 종료하세요.
메뉴 데이터의 기존 상대 경로 때문에 반드시 backend 폴더에서 실행합니다.

프런트엔드 터미널: 프로젝트 루트에서
  cd frontend\nextjs_jwt
  npm install
  npm run dev

.env.local의 NEXT_PUBLIC_API_SERVER가 백엔드 주소(예: http://localhost:8000)인지
확인한 뒤 프런트엔드를 실행합니다. 브라우저에서 Next.js가 표시하는 주소로 접속합니다.

3. 회원가입의 흐름
------------------
Header -> AuthModal -> services/api.js의 signup -> POST /auth/signup
1) 브라우저 폼은 이메일/비밀번호/연락처를 JSON으로 보냅니다.
2) FastAPI의 SignupRequest가 입력값을 검사하고 이메일을 소문자로 통일합니다.
3) 서버는 같은 이메일이 있으면 409를 반환합니다.
4) 계정마다 무작위 salt를 만들고 PBKDF2-HMAC-SHA256을 반복해 비밀번호 해시를 만듭니다.
5) backend/storage/user.json에 이메일, 연락처, salt, 해시만 기록합니다.
   원래 비밀번호는 저장하거나 응답하지 않습니다. 이 파일은 첫 가입 시 생성되고
   개인정보가 있으므로 Git에서 제외합니다. 파일을 공개하거나 수업 자료로 배포하지 마세요.
6) 성공하면 로그인 모달로 바뀝니다. 회원가입과 로그인은 별도 작업입니다.

4. 로그인의 흐름과 JWT
----------------------
AuthModal -> POST /auth/login -> AuthProvider -> Header
1) 서버는 입력한 비밀번호와 저장된 salt로 다시 해시를 만들어 저장된 해시와 비교합니다.
2) 성공하면 서버는 sub(이메일), exp(만료 시각)를 넣고 비밀 키로 HS256 서명을 합니다.
3) JWT는 header.payload.signature 형태입니다. payload는 암호화되지 않으므로
   비밀번호나 연락처를 넣지 않습니다. 서명은 내용의 위변조를 확인하기 위한 것입니다.
4) 클라이언트는 토큰을 sessionStorage에 보관하고 사용자 상태를 Context로 공유합니다.
   탭을 새로고침하면 GET /auth/me에서 서버에 서명, 만료, 사용자 존재를 다시 확인합니다.
   탭을 닫으면 해당 탭의 토큰은 사라집니다.
5) 로그아웃은 브라우저에서 토큰을 삭제합니다. JWT는 1시간 후 만료됩니다.
   이미 복사된 JWT는 로그아웃만으로 서버에서 즉시 폐기되지 않습니다.

5. 글쓰기 권한 검사
------------------
메뉴 등록 페이지는 로그인 전 폼 대신 안내문을 표시합니다. 하지만 브라우저 화면만
막으면 API를 직접 호출할 수 있습니다. 따라서 실제 보안 경계는 서버입니다.
폼은 FormData와 Authorization: Bearer <JWT> 헤더를 POST /menus에 보냅니다.
FastAPI의 Depends(current_user)가 저장 전에 서명, 만료, 계정 존재를 검사합니다.
토큰이 없거나 위조/만료되었으면 401이고 메뉴와 파일은 저장되지 않습니다.
토큰이 만료된 뒤 등록하면 안내 후 로그아웃 상태로 돌아갑니다.
파일의 Content-Type은 직접 지정하지 않아 브라우저가 multipart boundary를 만듭니다.

6. 실습 순서
------------
1) 손님 상태에서 메뉴 등록 페이지로 이동하고 안내문을 확인합니다.
2) 회원가입 후 같은 이메일로 다시 가입해 중복 오류를 확인합니다.
3) 잘못된 비밀번호로 로그인해 오류를 확인하고, 올바르게 로그인합니다.
4) Header의 이메일 앞부분과 새로고침 후의 로그인 상태를 확인합니다.
5) 메뉴와 첨부파일을 등록하고 목록 및 다운로드를 확인합니다.
6) 로그아웃 후 등록 폼이 사라지는지 확인합니다.
7) 개발자 도구 또는 API 클라이언트에서 토큰 없이 POST /menus를 호출해 401을 확인합니다.

7. 제한과 보안
---------------
이 예제는 교육용 단일 프로세스 서버와 JSON 파일 저장을 전제로 합니다. Lock은 같은
프로세스의 동시 가입만 보호하며 여러 워커/서버 간 쓰기를 조정하지 못합니다.
실서비스에는 데이터베이스의 고유 제약과 트랜잭션, HTTPS, 적절한 CORS, 로그인
시도 제한, 계정 복구와 비밀번호 변경, 토큰 폐기/갱신 정책이 필요합니다.
sessionStorage의 토큰은 같은 출처의 JavaScript에서 읽을 수 있어 XSS에 취약합니다.
운영 환경에서는 HttpOnly/Secure 쿠키와 CSRF 방어 등 별도 설계를 검토하세요.
서명 키 변경은 모든 기존 토큰을 무효화합니다. 로그아웃 후 탈취된 토큰도 만료 전까지
유효하며, 데이터 파일과 서버의 접근 권한 및 백업을 안전하게 관리해야 합니다.

8. 자동 확인
------------
backend 폴더에서:
  .\.venv\Scripts\python.exe -m unittest testcode.test_main_file_eazy_jwt
테스트는 임시 폴더와 가짜 AI 모듈을 사용하며 실제 회원/메뉴 데이터를 수정하지 않습니다.
