0. 컴포넌트 만들기와 렌더링 (약 10분)
-----------------------------------

[강사]
React에서 화면을 만드는 기본 단위는 컴포넌트입니다. 컴포넌트는 보통 화면의 한 부분을
담당하는 함수입니다. 이 함수가 JSX를 반환하면 React가 그 내용을 화면에 표시합니다.

[따라 하기: app/lecture/Greeting.js 같은 파일을 만들거나 기존 실습 폴더에서 실행]

function Greeting() {
  return <h1>안녕하세요, 메뉴 수업입니다!</h1>;
}

export default function App() {
  return (
    <main>
      <Greeting />
      <p>컴포넌트를 화면에 배치했습니다.</p>
    </main>
  );
}

[강사 질문]
Q. Greeting 함수만 만들고 <Greeting />을 사용하지 않으면 화면에 나타날까요?
A. 나타나지 않습니다. 컴포넌트를 정의하는 것과 화면에 렌더링(그리는 것)은 별개의 일입니다.

Q. <Greeting />과 greeting()은 같은 뜻인가요?
A. 아닙니다. React에서는 컴포넌트를 JSX 태그처럼 사용합니다. 일반 함수 호출과 달리
   React가 컴포넌트의 렌더링과 갱신을 관리할 수 있습니다.

[자세히 알아둘 단어]
- 컴포넌트(Component): UI를 역할별로 나눈 재사용 가능한 단위. 컴포넌트는 기본적으로 화면을 만드는 함수
- JSX: JavaScript 안에서 HTML과 비슷한 문법으로 UI를 표현하는 방식. return안에 있는 코드  특히 Greeting과 같이 개발자가가 
       발자가 직접 만든 리액트 컴포넌트를 태그처럼 불러와 사용하는 것도 JSX 문법의 핵심
- 렌더링(Rendering): 컴포넌트의 현재 결과를 화면에 반영하는 과정.
- export default: 파일에서 대표로 내보내는 값. import할 때 중괄호 없이 가져옵니다.


0-1. useState의 상태 변수와 setter 이해하기 (약 10분)
---------------------------------------------------

[강사]
화면이 바뀌어야 하는 값은 상태(state)로 관리합니다. useState는 현재 값과 그 값을
변경하는 함수를 한 쌍으로 제공합니다.

[간단한 예제]

"use client";

import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);

  return (
    <section>
      <p>현재 숫자: {count}</p>
      <button onClick={() => setCount(count + 1)}>1 증가</button>
    </section>
  );
}

[강사 설명]

훅(Hook)이란?
훅은 React 컴포넌트에서 특별한 기능을 사용할 수 있도록 연결해 주는 함수야.
일반적인 자바스크립트 함수와 달리 React가 제공하는 특별한 기능을 사용할 수 있어.
예를 들어 다음과 같은 기능이 있어.
훅                	역할
useState()     	컴포넌트의 상태(값)를 관리
useEffect()   	특정 상황에서 작업을 실행
useRef()	      값이나 DOM 요소의 참조를 관리
useContext()	  여러 컴포넌트에서 공통 데이터 공유
useMemo()	      계산 결과를 기억하여 불필요한 재계산 방지

1. 컴포넌트는 기본적으로 화면을 만드는 함수야.
function Counter() {
  return (
    <div>
      <p>안녕하세요!</p>
    </div>
  );
}
이 함수는 화면을 만들어 주는 역할을 해.

그런데 화면을 만들다 보면 추가로 필요한 기능들이 있어.
- 숫자를 기억하고 싶다.
- 버튼을 누르면 숫자를 변경하고 싶다.
- 특정 시점에 작업을 실행하고 싶다.
이런 기능을 React가 제공하는데, 그것을 사용할 수 있게 해주는 것이 **훅(Hook)**이야.


훅 - useState() 
useState(0)의 0은 첫 화면에 사용할 초기값입니다. 초기값이 숫자라는 의미이다. 배열 구조 분해 결과인 count는 현재
상태값이고 setCount는 상태를 바꾸는 setter 함수입니다. setter를 호출하면 React가 새
상태를 저장하고 컴포넌트를 다시 렌더링합니다. count를 직접 대입해 바꾸지 않습니다.

[강사 질문]
Q. count의 이름을 total로 바꾸면 동작할까요?
A. 네. 상태 변수 이름과 setter 이름은 개발자가 정합니다. 다만 짝이 분명하도록 보통
   [count, setCount], [menus, setMenus]처럼 씁니다.

Q. setCount(count + 1)을 호출하면 왜 숫자가 화면에 다시 표시될까요?
A. 상태 setter가 상태 변경을 React에 알리고, React가 해당 컴포넌트를 다시 렌더링하기
   때문입니다.

[자세히 알아둘 단어]
- 상태(State): 화면에 영향을 주며 변경될 수 있는 컴포넌트의 데이터.
- 초기값(Initial value): 상태를 처음 만들 때 지정하는 값.
- setter: 상태를 변경하도록 React에 요청하는 함수. 보통 set + 상태 이름 형식으로 짓습니다.
- 재렌더링(Re-render): 상태나 props 등이 바뀌었을 때 컴포넌트 결과를 다시 계산하는 일.


"use client";

import { useState } from "react";

export default function Counter() {
  const [count, setCount] = useState(0);

  // 새롭게 추가한 배열
  const menus = ["김밥", "라면", "돈까스", "비빔밥"];

  return (
    <section>
      <p>현재 숫자: {count}</p>
      <button onClick={() => setCount(count + 1)}>1 증가</button>

      <hr />

      <h3>메뉴 목록</h3>

      {menus.map((menu, index) => (
        <p key={index}>
          {index + 1}. {menu}
        </p>
      ))}
    </section>
  );
}


1~3. 레이아웃과 children 방식 (약 15분)
--------------------------------------

[강사]
페이지마다 헤더를 복사하는 대신 공통 레이아웃을 한 번 만들고, 페이지가 들어갈 자리에
children을 배치할 수 있습니다.

[일반 React 예제]

function SiteLayout({ children }) {
  return (
    <div>
      <header>메뉴 관리</header>
      <main>{children}</main>
    </div>
  );
}

export default function App() {
  return (
    <SiteLayout>
      <h1>오늘의 메뉴</h1>
      <p>페이지 내용입니다.</p>
    </SiteLayout>
  );
}

[강사 설명]
<SiteLayout>과 </SiteLayout> 사이에 넣은 내용은 SiteLayout의 children prop으로
전달됩니다. 레이아웃은 공통 구조를 제공하고 children 자리에는 현재 페이지 내용이 들어갑니다.

[실제 프로젝트 확인: app/layout.js]
프로젝트의 RootLayout은 Header, ChatSidebar, 공통 영역을 렌더링하고, <main> 안의
{children}에 현재 경로의 페이지를 배치합니다. 예를 들어 /menus에서는 메뉴 페이지가
children 자리에 표시됩니다.

[강사 질문]
Q. children은 특별한 React 예약어인가요?
A. React가 자식 요소를 전달할 때 사용하는 관례적인 prop 이름입니다. 컴포넌트에 태그
   사이의 내용을 넣으면 children으로 전달됩니다.

Q. children이라는 이름 대신 content라고 지으면 안 되나요?
A. 별도 prop으로 content를 직접 전달할 수는 있지만, 태그 사이의 자식 내용을 자동으로
   받으려면 정해진 이름인 children을 사용합니다.

[자세히 알아둘 단어]
- 레이아웃(Layout): 여러 페이지가 함께 쓰는 헤더·사이드바·공통 틀.
- children: 컴포넌트의 여는 태그와 닫는 태그 사이에 작성한 자식 요소.
- 중첩(Nesting): 한 컴포넌트 안에 다른 컴포넌트를 포함하는 구조.


4. 첫 화면을 출력한다: app/page.js (약 10분)
-----------------------------------------

[강사]
Next.js App Router에서 app/page.js는 루트 URL(/)의 페이지입니다. 먼저 메뉴 카드 모양을
분리하지 않고 목록 데이터에 맞춰 화면에 직접 반복 출력해 봅니다.

[간단한 예제]

const menus = [
  { id: 1, name: "비빔밥", calories: 550 },
  { id: 2, name: "김밥", calories: 420 }
];

export default function Home() {
  return (
    <ul>
      {menus.map((menu) => (
        <li key={menu.id}>
          {menu.name} - {menu.calories} kcal
        </li>
      ))}
    </ul>
  );
}

[강사 질문]
Q. map은 여기서 어떤 일을 하나요?
A. menus의 각 항목을 화면 요소로 바꾸어 새 배열을 만듭니다.

Q. key는 왜 필요한가요?
A. React가 반복 목록의 각 항목을 구별해 추가·삭제·변경을 효율적으로 반영하도록 돕습니다.
   목록에서는 각 데이터의 고유한 id를 key로 쓰는 것이 좋습니다.

[자세히 알아둘 단어]
- 배열(Array): 여러 값을 순서대로 담는 자료구조.
- map: 배열 각 항목을 다른 값(여기서는 JSX 요소)으로 변환하는 배열 메서드.
- key: 반복 렌더링되는 형제 요소를 식별하는 고유한 값.


5. useEffect 이해하기 (약 15분)
------------------------------

[강사]
메뉴 데이터는 서버에서 가져옵니다. 화면을 처음 보여준 뒤 데이터를 요청하는 작업처럼
렌더링 이외의 일을 처리할 때 useEffect를 사용합니다.

[의존성 배열 비교]

useEffect(() => {
  console.log("렌더링 후 실행");
});

useEffect(() => {
  console.log("처음 마운트된 뒤 실행");
}, []);

useEffect(() => {
  console.log("처음과 keyword가 바뀐 뒤 실행");
}, [keyword]);

[설명]
- 두 번째 인자를 생략하면 컴포넌트가 렌더링될 때마다 effect가 실행됩니다.
- []를 전달하면 컴포넌트가 처음 화면에 나타난 뒤 실행됩니다.
- [keyword]처럼 변수를 넣으면 처음 나타난 뒤와 keyword가 바뀐 뒤 실행됩니다.
- effect 안에서 상태를 무조건 바꾸면 반복 렌더링이 생길 수 있으므로 실행 조건을 생각합니다.

[실제 프로젝트 확인: app/page.js]
useEffect 안에서 getAllMenus()를 호출하고, 응답 데이터 중 일부를 골라 menus 상태에
저장합니다. 로딩 중에는 안내 문구를, 완료 후에는 추천 메뉴를 표시합니다.

[강사 질문]
Q. 빈 배열 []은 "아무것도 실행하지 않는다"는 뜻인가요?
A. 아닙니다. 처음 마운트된 후 한 번 실행하고, 이후 의존성이 없어 다시 실행하지 않는다는
   뜻입니다.

Q. [keyword]를 사용하면 keyword가 바뀔 때 어떤 일이 일어나나요?
A. effect가 다시 실행됩니다. 따라서 검색 키워드가 바뀔 때마다 요청하는 검색 기능을
   만들 수 있습니다. 현재 프로젝트는 검색 제출 시 loadMenus를 직접 호출합니다.

[자세히 알아둘 단어]
- effect(부수 효과): 화면 계산 외에 데이터 요청, 타이머 설정처럼 외부와 상호작용하는 작업.
- 의존성 배열: effect가 다시 실행될 조건으로 감시할 값들의 배열.
- 마운트(Mount): 컴포넌트가 처음 화면에 표시되는 것.
- 비동기(Async): 작업이 끝날 때까지 기다리는 동안 다른 작업을 진행할 수 있는 방식.
- await: Promise 작업의 완료를 기다린 뒤 결과를 받는 문법.


6. 컴포넌트 분리와 props (약 10분)
---------------------------------

[강사]
목록 전체를 관리하는 화면과 메뉴 한 건을 그리는 카드는 역할이 다릅니다. 반복되는 카드
UI를 MenuCard로 분리하고 필요한 메뉴 데이터를 props로 전달합니다.

[간단한 예제]

function MenuCard({ menu }) {
  return (
    <article>
      <h3>{menu.name}</h3>
      <p>{menu.calories} kcal</p>
    </article>
  );
}

function MenuList({ menus }) {
  return menus.map((menu) => <MenuCard key={menu.id} menu={menu} />);
}

[설명]
부모가 <MenuCard menu={menu} />라고 쓰면 자식은 props에서 menu를 받습니다. 실제
프로젝트의 app/page.js는 <MenuCard menu={menu} />로 데이터를 넘기고,
components/MenuCard.js는 { menu }를 받아 카드 내용을 그립니다.

[강사 질문]
Q. "probs"가 맞는 단어인가요?
A. 아니요. 정확한 표기는 props입니다. properties(속성)에서 온 표현입니다.

Q. 자식 컴포넌트에서 부모의 menus 상태를 바로 읽을 수 있나요?
A. 자동으로 읽을 수 없습니다. 부모가 필요한 데이터를 props로 전달해야 합니다.

[자세히 알아둘 단어]
- props: 부모 컴포넌트가 자식 컴포넌트에 전달하는 입력값. 함수 매개변수와 비슷합니다.
- 분리(Extract): 큰 UI의 일부를 별도 컴포넌트로 옮겨 역할을 나누는 것.
- 재사용성: 같은 컴포넌트를 다른 데이터나 위치에서도 활용할 수 있는 정도.


7. /menus 경로로 이동하기 (약 10분)
----------------------------------

[실제 프로젝트 확인]
app/menus/page.js가 /menus 경로를 담당합니다. App Router에서는 app 아래의 폴더 이름이
URL 경로가 되고, 그 폴더 안의 page.js가 해당 경로의 페이지가 됩니다.
예: app/menus/page.js -> /menus
예: app/menus/new/page.js -> /menus/new

[강사 질문]
Q. 라우터를 사용하려면 반드시 app 아래에 페이지를 만들어야 하나요?
A. 이 프로젝트는 App Router를 사용하므로 페이지 경로를 app 디렉터리에 만듭니다.
   관례적으로 프로젝트 루트의 app/ 또는 src/app/을 사용합니다. Next.js에는 별도의
   Pages Router 방식도 있어 pages/를 사용하는 프로젝트도 있지만, 두 방식을 혼동하지
   말고 현재 프로젝트의 라우터 구조를 따라야 합니다.

Q. import 경로에서 @는 항상 루트를 의미하나요?
A. 항상 그런 것은 아닙니다. 프로젝트 설정에 따라 달라집니다. 이 프로젝트의
   jsconfig.json에는 "@/*": ["./*"]로 설정되어 있어 @/components/MenuCard는
   frontend/nextjs/components/MenuCard를 가리킵니다. @ 자체가 JavaScript 문법으로
   루트를 의미하는 것은 아닙니다.

[자세히 알아둘 단어]
- 라우팅(Routing): URL에 따라 보여줄 페이지를 선택하는 일.
- App Router: Next.js에서 app 디렉터리와 page.js, layout.js 규칙으로 구성하는 라우팅 방식.
- 별칭(Alias): 긴 경로를 짧은 이름으로 표현하도록 설정한 import 경로.


8~9. 콜백, 부모·자식 역할 분담 (약 15분)
---------------------------------------

[강사]
메뉴 목록 페이지(MenusPage)가 데이터를 가져오고 MenuTable이 표를 그린다고 합시다.
표에서 삭제나 추천 후 목록을 새로 읽으려면 자식이 부모의 loadMenus 기능을 요청해야
합니다. 이때 부모가 함수를 props로 전달합니다. 이처럼 전달받아 나중에 실행하는 함수를
콜백 함수라고 부릅니다.

[간단한 예제]

function Parent() {
  function refresh() {
    console.log("부모가 목록을 새로 불러옵니다.");
  }

  return <Child onRefresh={refresh} />;
}

function Child({ onRefresh }) {
  return <button onClick={onRefresh}>새로고침 요청</button>;
}

[실제 프로젝트 확인]
app/menus/page.js는 <MenuTable menus={menus} onRefresh={loadMenus} />로 메뉴 데이터와
새로고침 함수를 전달합니다. components/MenuTable.js는 삭제나 추천 요청이 성공한 뒤
await onRefresh()를 호출합니다.

[강사 질문]
Q. onChange처럼 onRefresh도 React가 정해 놓은 이름인가요?
A. 아닙니다. onChange는 React 입력 요소에서 흔히 쓰는 이벤트 prop 이름이고,
   onRefresh는 이 프로젝트에서 개발자가 정한 일반 prop 이름입니다. onReload,
   afterDelete처럼 바꿀 수 있지만 부모와 자식에서 이름을 일치시켜야 합니다.

Q. 꼭 on으로 시작해야 하나요?
A. 문법 규칙은 아닙니다. 이벤트나 콜백임을 알아보기 쉽게 onSave, onRefresh처럼
   이름을 짓는 관례입니다.

Q. 왜 부모가 데이터를 가져오고 자식은 표만 그리도록 나누나요?
A. 데이터와 페이지 흐름은 페이지 컴포넌트가 관리하고, 표 컴포넌트는 표시와 사용자
   동작을 맡으면 각 컴포넌트의 책임이 명확해집니다. 자식은 필요한 동작을 콜백으로
   부모에게 요청합니다.

[용어 정리]
- 콜백(Callback): 다른 함수나 컴포넌트에 전달되어 특정 시점에 호출되는 함수.
- 이벤트 핸들러(Event handler): 클릭, 입력, 제출 같은 이벤트가 발생했을 때 실행되는 함수.
- 책임 분리(Separation of concerns): 데이터 관리, 표시, 저장처럼 역할을 나누는 설계.
- 부모/자식: JSX 안에 다른 컴포넌트를 포함하는 쪽이 부모, 포함된 쪽이 자식입니다.

[강사 보충]
기존 메모의 "/menus/app.js"는 실제 파일 경로와 다릅니다. 이 프로젝트의 목록 페이지는
app/menus/page.js이며, MenuTable의 부모가 MenusPage입니다. MenuTable의 파일명은
components/MenuTable.js입니다.


10. 메뉴 삭제 흐름 (약 10분)
---------------------------

[강사]
삭제 버튼을 누르면 MenuTable의 handleDelete가 실행됩니다. 먼저 사용자에게 확인을 받고,
확인한 경우 deleteMenu(id)로 서버에 삭제를 요청합니다. 성공하면 onRefresh()로 목록을
다시 가져옵니다.

[간단한 예제]

async function handleDelete(id) {
  if (!confirm("정말 삭제할까요?")) return;
  await deleteMenu(id);
  await onRefresh();
}

<button onClick={() => handleDelete(menu.id)}>삭제</button>

[질문]
Q. onClick={handleDelete(menu.id)}라고 바로 쓰면 안 되나요?
A. 그렇게 쓰면 렌더링 중에 함수가 즉시 실행됩니다. 클릭했을 때 실행하도록
   onClick={() => handleDelete(menu.id)}처럼 함수를 전달합니다.

Q. 왜 id를 넘기나요?
A. 서버가 어떤 메뉴를 삭제할지 알아야 하기 때문입니다. 메뉴마다 고유한 id를 요청에 씁니다.

[자세히 알아둘 단어]
- 확인 대화상자(confirm): 사용자가 동작을 계속할지 확인하는 브라우저 대화상자.
- id(식별자): 데이터 항목을 서로 구별하는 값.
- API 요청: 프런트엔드가 서버에 조회·등록·수정·삭제 같은 작업을 요청하는 것.


11. 메뉴 추천 흐름 (약 5분)
--------------------------

[강사]
추천 버튼은 recommendMenu(id)를 호출하고, 성공 후 목록을 새로고침합니다. 삭제와 흐름은
비슷하지만 서버에 보내는 동작과 서버가 바꾸는 데이터가 다릅니다.

[간단한 예제]

async function handleRecommend(id) {
  await recommendMenu(id);
  await onRefresh();
}

<button onClick={() => handleRecommend(menu.id)}>추천</button>

[질문]
Q. 추천 횟수는 브라우저에서 직접 증가시키면 안 되나요?
A. 이 프로젝트에서는 서버가 추천 데이터를 관리합니다. 서버 요청이 성공한 뒤 최신 목록을
   다시 불러오면 서버 데이터와 화면이 일치합니다.

[자세히 알아둘 단어]
- 서버(Server): 데이터 저장과 처리를 담당하는 프로그램.
- 동기화(Synchronization): 화면과 서버의 데이터가 같은 상태를 유지하도록 맞추는 것.


12~13. 메뉴 등록: 직접 처리와 콜백 비교 (약 15분)
------------------------------------------------

[강사]
등록 폼에서 사용자가 입력한 값을 객체로 만들고 서버에 저장합니다. 현재 구현은
MenuInputForm이 입력, API 요청, 이동까지 직접 처리합니다. 동작은 간단하지만 폼과 페이지
흐름이 한 컴포넌트에 함께 들어갑니다.

[현재 구조의 핵심: components/MenuInputForm.js]
1. event.preventDefault()로 브라우저의 기본 폼 제출(페이지 새로고침)을 막습니다.
2. new FormData(event.target)으로 입력값을 읽습니다.
3. 메뉴 객체를 만들고 Number(...)로 칼로리를 숫자로 변환합니다.
4. addMenu(menuObject)를 호출한 다음 성공하면 /menus로 이동합니다.

[간단한 현재 방식]

async function handleSave(event) {
  event.preventDefault();
  const formData = new FormData(event.target);
  const menuObject = {
    name: formData.get("name"),
    calories: Number(formData.get("calories")),
    description: formData.get("description")
  };
  await addMenu(menuObject);
  router.push("/menus");
}

[강사 질문]
Q. 콜백 없이도 등록이 되는데 왜 콜백을 배우나요?
A. 한 컴포넌트에 입력, 서버 저장, 화면 이동을 모두 넣을 수도 있지만, 컴포넌트가 커지고
   책임이 섞일 수 있습니다. 저장과 이동을 부모 페이지가 담당하도록 분리하는 방법도
   익히면 컴포넌트의 역할과 재사용성을 조절할 수 있습니다.

[13단계: 콜백으로 역할을 분리한 개념 예제]

"use client";

import { useRouter } from "next/navigation";
import { addMenu } from "@/services/api";

// 부모 페이지
function NewMenuPage() {
  const router = useRouter();

  async function handleSave(menuObject) {
    await addMenu(menuObject);
    router.push("/menus");
  }

  return <MenuInputForm onSave={handleSave} />;
}

// 자식 폼
function MenuInputForm({ onSave }) {
  async function handleSubmit(event) {
    event.preventDefault();
    const formData = new FormData(event.target);
    const menuObject = {
      name: formData.get("name"),
      calories: Number(formData.get("calories")),
      description: formData.get("description")
    };
    await onSave(menuObject);
  }

  return <form onSubmit={handleSubmit}>{/* 입력 항목 */}</form>;
}

[강사 설명]
콜백 방식에서는 자식이 메뉴 객체를 만들고 onSave(menuObject)로 부모에게 전달합니다.
부모가 저장과 이동을 담당합니다. 실제 프로젝트의 NewMenuPage와 MenuInputForm은 현재
콜백 방식이 아니라 폼 컴포넌트 안에서 API 저장과 라우팅을 처리하는 구조입니다.
위 코드는 두 방식을 비교해 책임 분리 개념을 배우기 위한 예제입니다.

[강사 질문]
Q. formData.get("calories")는 숫자인가요?
A. 일반적으로 입력에서 읽은 값은 문자열입니다. 칼로리처럼 숫자로 쓸 값은
   Number(...)로 변환해야 합니다.

Q. event.preventDefault()는 무엇을 막나요?
A. 폼 제출 시 브라우저가 기본적으로 페이지를 새로고침하거나 이동하는 동작을 막고,
   JavaScript 코드가 제출을 처리하도록 합니다.

[자세히 알아둘 단어]
- FormData: form 안의 name이 있는 입력값을 읽고 다루는 브라우저 객체.
- event.target: 이벤트가 발생한 대상. 폼 submit 이벤트에서는 제출된 form 요소입니다.
- 객체(Object): 이름과 값의 쌍으로 데이터를 묶은 구조. 예: { name: "비빔밥" }.
- 기본 동작(Default behavior): 브라우저가 별도 코드 없이 제공하는 기본 이벤트 처리.
- router.push: Next.js에서 지정한 경로로 이동시키는 클라이언트 측 내비게이션.


14. 동적 경로로 메뉴 수정 (약 15분)
----------------------------------

[강사]
각 메뉴의 수정 화면은 메뉴마다 다릅니다. id를 URL에 넣어 /menus/12/edit처럼 표현할 수
있습니다. app/menus/[id]/edit/page.js에서 대괄호로 감싼 [id]가 동적 경로 구간입니다.

[경로 대응]
app/menus/[id]/edit/page.js -> /menus/12/edit, /menus/25/edit 등
여기서 12 또는 25가 id 값입니다.

[실제 프로젝트 확인: app/menus/[id]/edit/page.js]
useParams()에서 id를 읽고 getMenuOne(id)로 메뉴를 조회합니다. 조회된 메뉴를 menu 상태에
넣은 뒤 MenuModifyForm에 initialData로 전달합니다. 저장 버튼을 누르면 폼이 onSave
콜백으로 객체를 부모에 전달하고, 부모의 handleSave가 updateMenu와 페이지 이동을 담당합니다.

[실제 프로젝트 확인: components/MenuTable.js]
<Link href={`/menus/${menu.id}/edit`}>수정</Link>에서 각 메뉴의 id를 경로에 넣습니다.
템플릿 문자열의 ${menu.id} 자리에 실제 값이 들어갑니다.

[강사 질문]
Q. 수정 id를 함수 인자로만 넘기지 않고 URL에 넣는 이유는 무엇인가요?
A. URL만 봐도 어떤 메뉴의 수정 화면인지 표현할 수 있고, 새로고침하거나 주소를 공유해도
   같은 메뉴 화면으로 접근할 수 있습니다. id를 함수 인자로 전달하는 방식도 가능하지만,
   이 예제에서는 동적 경로를 학습합니다.

Q. [id]라는 폴더 이름 자체가 메뉴 ID인가요?
A. 아닙니다. [id]는 동적 구간을 표시하는 파일·폴더 규칙입니다. 실제 id 값은 사용자가
   /menus/12/edit처럼 접속했을 때 URL에서 읽어 옵니다.

Q. MenuModifyForm에서 입력값은 어떻게 관리하나요?
A. name, calories, description을 각각 useState로 관리하고, input의 value와 onChange를
   연결합니다. 이를 제어 컴포넌트라고 합니다.

[간단한 수정 폼 예제]

"use client";

import { useState } from "react";

function NameEditor({ initialName, onSave }) {
  const [name, setName] = useState(initialName);

  return (
    <form
      onSubmit={(event) => {
        event.preventDefault();
        onSave({ name });
      }}
    >
      <input
        value={name}
        onChange={(event) => setName(event.target.value)}
      />
      <button type="submit">저장</button>
    </form>
  );
}

[자세히 알아둘 단어]
- 동적 경로(Dynamic route): URL 일부가 데이터에 따라 달라지는 경로.
- useParams: 현재 URL의 동적 경로 값에 접근하는 Next.js 내비게이션 훅.
- 제어 컴포넌트(Controlled component): React 상태가 입력 요소의 현재 값을 관리하는 방식.
- 템플릿 문자열: 백틱(`) 안에 ${표현식}을 넣어 문자열을 만드는 문법.
- 초기 데이터(initialData): 수정 화면을 열 때 기존 메뉴에서 가져온 값.
